# Бот-витрина для Kwork

Один бот — три типовых бота, которые чаще всего заказывают малому бизнесу:

| Режим | Что делает | Для кого продавать |
|---|---|---|
| 📅 **Онлайн-запись** | Услуга → мастер → день → свободное время → телефон. «Мои записи» с отменой, напоминание за 2 часа, защита от двойной записи на одно время | Барбершопы, салоны, ногти, массаж, автосервисы, репетиторы, клиники |
| 🛒 **Магазин** | Категории → товар (± в корзину) → корзина → имя, телефон, доставка или самовывоз, адрес → онлайн-оплата или при получении. Бесплатная доставка от суммы | Кофейни, доставка еды, цветы, одежда, хендмейд |
| 📝 **Квиз-калькулятор** | 4 вопроса → ориентир цены → телефон → горячая заявка менеджеру | Ремонт, окна, мебель, натяжные потолки, юристы, курсы |

**Админка владельца** (`/admin`): статистика, записи на сегодня, последние заказы и заявки,
выгрузка всего в Excel (CSV), рассылка всем пользователям бота.

**Демо-режим** (`DEMO_MODE=true`): после каждой записи, заказа или заявки клиент видит,
какое уведомление получит владелец. Это главный аргумент на продаже: человек сам чувствует
«мне на телефон будут падать заявки».

## Запуск (с телефона)

1. @BotFather → `/newbot` → имя вроде «Jack Bots — демо» → токен. Свой ID узнай у @getidsbot.
2. GitHub: новый репозиторий → загрузи все файлы этой папки (с папкой `handlers`).
3. Railway: New Project → Deploy from GitHub repo.
   - Variables по образцу `env.example`: минимум `BOT_TOKEN`, `ADMIN_IDS`, `CONTACT`.
   - Settings → Volumes → Add Volume, путь `/data`, иначе записи и заказы пропадут при перезапуске.
4. Напиши боту `/start`. Ссылку `t.me/имя_бота` вставляй в каждый кворк и отклик.

## Два бота: клиентский и служебный

По умолчанию всё в одном боте: клиенты оформляют, владельцу туда же приходят уведомления и работает /admin.
Чтобы разделить:

1. Создай у @BotFather второго бота, например «Jack Bots — админ».
2. В Railway добавь переменную `ADMIN_BOT_TOKEN` с его токеном → Deploy.
3. Открой служебного бота и нажми /start. Сразу откроется админка, и сюда же будут приходить новые записи, заказы и заявки.

Клиентский бот остаётся чистым: в меню нет /admin. Рассылка из служебного бота уходит клиентам через клиентского бота.
Чужим служебный бот отвечает «доступ закрыт». Пускает только ID из `ADMIN_IDS`.
Оба бота работают в одном сервисе Railway, второй сервис не нужен.

## Как сделать бота заказчику за вечер

1. Скопируй репозиторий.
2. В `data.py` замени название, адрес, часы работы, услуги, мастеров с выходными, товары и вопросы квиза.
   Ничего, кроме этого файла, менять не нужно.
3. Ненужные режимы убери из меню в `handlers/common.py` (функция `main_menu`). Например, барбершопу оставь только запись.
4. Новый бот у @BotFather на имя заказчика, `ADMIN_IDS` — Telegram ID заказчика, `DEMO_MODE=false`.
5. Оплата: заказчик подключает ЮKassa у @BotFather (Payments), токен идёт в `PAYMENT_TOKEN`.
   Сначала тестовый токен, проверь оплату тестовой картой.
6. Сервер: отдельный проект Railway на аккаунте заказчика (он платит хостинг сам) или на твоём
   за абонентскую плату. Это стоит обсудить в заказе.

## Технически

Python 3.11+, aiogram 3, SQLite (один файл на Volume). Файлы:

- `data.py` — каталог: всё, что меняется под клиента;
- `logic.py` — расчёт свободных слотов, корзина, оценка квиза (без Telegram, покрыто тестами);
- `db.py` — хранилище: пользователи, записи, корзины, заказы, заявки, выгрузка CSV;
- `handlers/` — сценарии: `menu`, `booking`, `shop`, `quiz`, `admin`, `fallback`;
- `bot.py` — запуск и напоминания;
- `test_bot.py` — 13 сценариев на подменённом Telegram (`python test_bot.py`).
